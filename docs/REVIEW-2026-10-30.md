## 二、本轮发现并修复的问题

| 问题 | 影响 | 修复 |
|---|---|---|
| `maas_request` 定义被函数插入覆盖 | 新聊天分析报 `name 'maas_request' is not defined` | 恢复独立 `maas_request()` 函数，聊天分析实测成功 |
| `wechat_engine` 在 `.env` 加载前导入 | `.env` 中的引擎端口/路径配置不生效 | 调整 import 顺序，先加载环境再导入引擎模块 |
| `CLIENTHUB_DATA_DIR` 在 `.env` 加载前读取 | 打包/自定义数据目录不生效 | 先加载 `.env`，再初始化数据目录 |
| 长聊天分析未限长 | 大会话可能超模型请求上限、看起来卡死 | 只取最近 800 条消息，并限制 18,000 字 |
| 日期过滤先拉完整历史 | 提取“今日”也要读取几千条消息，耗时数分钟 | 按开始日期倒序读取，跨过起始时间立即停止；实测 3,484 条历史的日期预览约 4.9 秒 |
| 项目字段固定写成“微信提取” | 客户 360 项目显示错误 | 增加 AI `project` 字段，按聊天内容推断；无明确项目显示“—” |
| 依赖外部 WeChatDataAnalysis 安装 | 换电脑还要安装原软件 | 复制 `wechat-backend.exe + native/` 到 `services/wechat-engine/`，并加入 electron-builder extraResources |
| 复制后的 native core 受工作区 ACL/低完整性影响 | 内置引擎报 broker 无法启动 | 对内置 exe/native 设置 Medium integrity；打包后文件由 NSIS 正常写入 |
| 提取任务同步等待 AI 解析 | 用户看不到进度、以为卡死 | 改为 Sidecar 异步任务，分阶段进度：读取会话 → 读取消息 → 筛选 → 创建记录 → AI 解析 |

## 四、剩余风险

1. **安装包还没有实际生成**
   - `electron-builder` 配置和 `scripts/build-installer.ps1` 已准备好；
   - 构建机需要安装 PyInstaller，先执行 `build:sidecar` 生成 `release/ai-sidecar/clienthub-ai.exe`；
   - 目标电脑只需要 ClientHub 安装包，不需要 Python 或 WeChatDataAnalysis。

2. **第三方后端体积**
   - 内置 `wechat-backend.exe` 约 165 MB，native core 约 34 MB，安装包会明显变大；
   - 升级微信版本时，需要同步更新内置后端和 native core。

3. **微信客户端依赖**
   - 目标电脑仍需安装并登录微信；密钥提取需要微信保持运行；
   - 微信版本变化可能导致 native core 不兼容，需要重新适配。

4. **媒体附件**
   - 图片/语音/视频/文件已进入附件索引；
   - 目前图片可预览，语音/视频/文件的原文件离线复制与语音转写仍可继续扩展。

5. **数据清理**
   - 本地测试产生了多条测试聊天记录（李昀卓、姐姐等）；
   - 正式交付前应清理测试数据，或提供“删除记录/清空演示数据”入口。
