# 客户需求澄清助手 PRD

状态：访谈完成，待实现

术语：**需求澄清单**指一次手动分析及其后续跟进的工作单，保存当次选中的资料、生成的问题、证据、提问状态、甲方回答和追问；它不是客户档案，也不是正式需求。复制问题结构后先生成“需求澄清单草稿”，再选择客户/项目和资料。

## 问题背景

软件开发乙方会从客户沟通、文件和其他已导入资料中逐步收到项目信息。信息分散时，乙方难以判断需求是否完整，也容易遗漏向甲方确认的关键问题。

## 目标

基于用户选定的已有资料梳理当前已知信息，并生成乙方向甲方澄清需求的问题，帮助项目进入范围明确、可评估和可推进的状态。

## 已确认需求

- 面向软件开发行业的乙方需求澄清场景。
- 问题需要结合已有客户信息生成，至少覆盖客户期待工期、一期功能范围等场景。
- 分析来源是 ClientAtlas 已导入的内容。
- 用户手动选择资料并手动发起分析，不自动选资料或自动分析。
- 选择资料时需要支持按客户、项目、未关联资料筛选，也需要支持跨项目、跨客户组合资料。
- 在筛选结果中既可逐条勾选，也可全选当前筛选结果。
- 分析来源覆盖所有现有可提取文本的导入内容，包括聊天、通话转写、文档/邮件解析和 OCR；附件使用已有解析或转写结果。
- 本产品继续遵守单机单用户边界。
- 老板本人是主要操作者，并直接使用问题清单向甲方提问；当前没有独立审核角色。
- 一次分析可以混选多个客户或项目，但结果必须按客户/项目分区，每个问题标明对应来源，避免不同甲方的信息混淆。
- 每条问题附提问理由、原文摘录、资料来源和时间，便于老板核对依据。
- 固定问题库覆盖业务目标/指标、用户与流程、一期范围、平台与交互、数据迁移、接口与第三方、权限/安全/合规、性能/可靠性、工期/预算/合同、验收/上线/运维/售后；每次分析只展示与所选资料相关或存在信息缺口的部分。
- 问题优先级分为“必须先确认”“重要”“后续确认”。“必须先确认”表示会阻塞范围/报价/工期判断；“重要”影响方案或成本但暂不阻塞；“后续确认”可留到设计、交付或运维阶段。
- 每个问题可标记为“待问”“已问”或“已回答”；老板可记录甲方回答，并基于回答继续生成追问。
- 记录回答后不自动调用模型；老板点击“基于回答生成追问”才开始生成。
- 甲方回答默认留在需求澄清单中；老板手动确认后，可将回答转为需求或用于更新项目。
- 回写回答前，老板选择目标客户/项目、预览字段变更并手动确认保存。
- 系统可推荐“转为需求”或“更新项目”，只预填甲方回答明确支持的字段，其他字段保持不变；老板预览后确认保存。
- 从甲方回答新建的需求默认状态为“待确认”，由老板确认需求范围后再改为“已确认”。
- 澄清问题的先问优先级与需求 P0/P1/P2 交付优先级分开判断；转为需求时可推荐 P0/P1/P2，由老板预览确认。
- 每次分析自动保存为可重新打开、继续编辑的需求澄清单，包含资料选择、问题、证据、状态、回答和追问。
- 需求澄清单默认按客户/项目和日期命名，老板可修改名称。
- 对同一客户/项目重新分析时保留旧记录快照，并新建分析记录。
- 资料出现相互矛盾的事实时，展示双方证据并生成“必须先确认”的问题，不由模型自行裁定。
- 已知事实、推断和未知缺口分开呈现；推断明确标记并附依据。
- 关键项未在资料中提及时，仍生成基础澄清问题，并标明“资料未提及/信息不足”及相关来源。
- 每次分析前展示本次客户/项目范围、材料数量、逐份资料的名称与类型，以及所用模型；老板确认后才发送资料进行分析。
- 问题生成复用设置中的默认文本模型。
- 模型未配置或调用失败时保留需求澄清单和已填回答，说明失败原因并提供重试。
- 清单保留所有相关问题，默认展开“必须先确认”，折叠“重要”和“后续确认”。
- 每个客户/项目分区内先按优先级分组，再按固定维度归类。
- 同一优先级下按固定行业维度顺序排列，保证不同分析结果稳定一致。
- 同一客户/项目中的重复问题合并，并汇总、标出所有相关依据；不同客户/项目之间不合并。
- MVP 首要成功指标为生成问题中被保留、复制或标记为“已问”的比例。
- 先用前 10 次完成的分析建立该指标基线，再设定目标。
- 首个 MVP 包含完整流程：资料选择、分析、问题编辑、提问状态/回答追踪、手动生成追问、转需求/更新项目、复制和 Word/PDF 导出。
- 模块在工作台侧栏有独立入口，并从客户/项目详情提供快捷入口。
- 独立入口默认显示历史需求澄清单列表，并提供新建分析入口。
- 历史列表支持按客户/项目、日期和未回答/已完成状态筛选。
- 所有保留问题都有回答或处理结论时，需求澄清单自动标记为已完成；问题被删除或标记为“不适用”也算处理结论。仍待提问或等待甲方答复时保持未完成。
- 老板可编辑或删除生成的问题、调整优先级，也可新增自定义问题。
- 问题清单可按客户/项目复制为文本，也可导出 Word/PDF。
- 复制文本仅包含问题；Word/PDF 导出前弹窗多选“必须先确认 / 重要 / 后续确认”（默认全选），显示各级及已选问题数量，空选不可导出，沿用客户/项目筛选。文档提供标题、问题数量、客户/项目分区、优先级与维度，每题引用保存的原文摘录作为依据，不以文件名替代原句；多条原句去重分行，不改写或截断，不附内部理由和模型信息。无原句的手动问题标为“手动补充（无原文依据）”，其他问题标为“未记录原文依据（待补充）”。
- 对外问题措辞简洁、礼貌、专业，每题聚焦一个事项。
- 问题默认使用简体中文，每次分析可切换语言。
- 所选资料超过单次模型输入长度时自动分批分析，再按客户/项目汇总结果。
- 分批分析显示已完成/总批次进度，并允许老板取消。
- 分析取消后保留已完成批次结果，需求澄清单标记为未完成，可继续重试剩余批次。
- 重试剩余批次默认沿用原资料和模型配置，老板可调整后再试。
- 历史需求澄清单可归档、恢复和删除；删除前需要确认。
- 归档需求澄清单默认从列表隐藏，可通过“包含已归档”筛选查看并恢复。
- 删除需求澄清单只删除工作单本身，引用的原始聊天、转写和文件保留。
- 需求澄清单可复制为新单，只复制问题结构和固定维度，不复制原回答及状态。
- 复制新单后重新选择客户/项目和资料。
- 复制后的需求澄清单先保存为草稿，选好客户/项目和资料后再进入发送确认。
- 草稿在历史列表中单独显示“草稿”状态，可继续补充资料或删除。
- 开始分析前至少要有一份可读资料；客户/项目可以后补，未分配前结果暂存为未归属。
- 未归属结果单独显示“未归属”分区，之后可批量分配客户/项目。
- 未归属结果可按问题或资料拆分分配到多个客户/项目；拆分后保留各自证据与来源。
- 拆分未归属结果只改变客户/项目归属，保留原问题和回答，不自动重新生成。
- 向已有需求澄清单追加资料时只分析新增资料，再与原结果去重合并。
- 历史澄清单可从资料库勾选其他已导入文件，选材区提供确认追加并继续分析入口；打开历史单或点击追加入口时重新读取资料，旧问题、回答和证据保留。
- 增量分析与旧结论冲突时保留旧证据，标出变化并新增“必须先确认”的冲突问题，不直接覆盖旧结论。
- 增量分析产生新问题或冲突时，需求澄清单自动标记为未完成，直到新增事项处理完。
- 问题被删除或标记为“不适用”都视为处理结论，不阻止需求澄清单完成。
- 问题标记为“已问”但尚未录入甲方回答时，仍保持未完成，直到回答或标记“不适用”。
- 部分所选资料无法提取文本或分析没有可用结果时，说明具体资料及原因，并允许老板移除或重新选择。
- 低置信度问题仍作为待核验项显示，并明确标注低置信度。
- 历史记录保留分析时的原文摘录、来源和时间；原始资料仍存在时，证据可跳回查看。

## 候选流程

1. 用户按客户、项目或资料状态筛选已有资料。
2. 用户逐条选择资料或全选当前筛选结果，可跨项目或跨客户组合；系统说明无法提取文本的资料及原因，老板可移除或重新选择。
3. 系统使用设置中的默认文本模型，并展示本次客户/项目范围、材料数量、每份资料的名称与类型和模型；开始分析前至少需要一份可读资料，客户/项目可以后补。老板可选择生成语言（默认简体中文），确认后手动发起分析，资料才会发送到大模型服务。
4. 系统基于聊天、通话转写、文档/邮件解析及 OCR 等已有文本，按客户/项目分区整理已知事实、推断和未知缺口并生成问题；未归属结果单独显示在“未归属”分区，之后可批量分配客户/项目，也可按问题或资料拆分到多个客户/项目，拆分只改变归属，保留原问题、回答、证据与来源，不自动重新生成。资料超过单次模型输入长度时自动分批分析，再按客户/项目汇总，并显示已完成/总批次进度，老板可取消。关键项未提及时仍生成基础澄清问题，明确标注“资料未提及/信息不足”及相关来源。推断明确标记并附依据；低置信度问题作为待核验项显示并标注低置信度。每个客户/项目下先按“必须先确认 / 重要 / 后续确认”分组，再按固定行业维度顺序排列，并附提问理由、原文摘录、来源和时间。优先级按是否阻塞范围/报价/工期判断、是否影响方案/成本及是否可留到后续阶段确定。遇到相互矛盾的信息时展示双方证据，生成“必须先确认”的问题。清单保留所有相关问题，默认展开“必须先确认”，折叠其余优先级。
5. 老板可编辑或删除问题、调整优先级、补充自定义问题，再按客户/项目复制为文本或导出 Word/PDF，用于向甲方提问；文本复制只含问题，Word/PDF 在选择优先级后采用文档排版并附每题原文依据。措辞简洁、礼貌、专业，每题聚焦一个事项；完整原文和内部理由保留在应用内。
6. 老板更新问题状态并记录回答；需要进一步确认时，手动点击“基于回答生成追问”。
7. 系统可推荐将回答转为需求或更新项目，只预填回答明确支持的字段；老板选择目标客户/项目、预览变更并确认保存。新建需求默认状态为“待确认”，需求 P0/P1/P2 与澄清优先级分开判断并由老板预览确认，老板确认需求范围后再改为“已确认”。
8. 分析自动保存为需求澄清单并按客户/项目和日期命名，老板可修改名称；之后可重新打开并继续编辑。向已有单追加资料时只分析新增资料，再与原结果去重合并；若与旧结论冲突则保留旧证据、标出变化并新增“必须先确认”的冲突问题，不直接覆盖旧结论；产生新问题或冲突时自动标记未完成，直到新增事项处理完。历史单可归档、恢复、删除或复制，删除前确认；删除只删除工作单，原始资料保留；复制只保留问题结构和固定维度，不复制回答及状态，先保存为需求澄清单草稿。草稿在历史列表中单独显示，可继续补充资料或删除；选好客户/项目和资料后再进入发送确认。归档单默认隐藏，可通过“包含已归档”筛选找回。同一客户/项目再次分析时新建澄清单，保留旧单快照。
9. 模型未配置或调用失败时，系统保留当前需求澄清单和已填回答，说明失败原因并提供重试；取消时保留已完成批次结果并可重试剩余批次，默认沿用原资料和模型配置，老板可调整后再试。

以上流程和边界已完成产品访谈，进入实现前的技术设计与拆分。
